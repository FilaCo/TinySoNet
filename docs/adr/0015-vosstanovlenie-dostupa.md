# ADR-0015: Восстановление доступа — перепривязка по кворуму

Статус: принято, 2026-09-21

## Контекст

Пользователь потерял единственное устройство. Отвязать себя нечем (отвязку подписывает другое устройство того же пользователя), голоса за себя у него нет. Остаётся повторный приём как новый пользователь — прошлые сообщения при этом остаются подписаны мёртвым ключом и приписаны тому, кого больше нет.

Альтернатива — фраза восстановления: ключ устройства выводится из seed, и новое устройство восстанавливает тот же ключ. Она держит долгосрочный ключ вне аппаратного хранилища постоянно, то есть добавляет риск класса A7 всем пользователям ради редкого сценария.

## Решение

Новый вид предложения — **перепривязка**: новый ключ устройства привязывается к существующему пользователю по кворуму, без участия старых устройств. Личность сверяется вне сети спонсором, как при вступлении (ADR-0008). Кворум — единогласие электората без цели. Цель в кворуме не считается, но её голос «нет» с ещё живого устройства закрывает заявку. Принятая перепривязка отвязывает все прежние устройства цели.

Правила — [design/04-membership.md](../design/04-membership.md), R1–R5.

## Последствия

- Отдельной машинерии не нужно: это предложение, голоса и кворум по общим правилам.
- Вето цели закрывает угон личности у того, кто устройство не терял.
- Кворум получает то, чего не даёт удаление, — возможность писать от имени цели. Смягчение только видимостью: событие перепривязки в журнале у всех.
- Долгосрочных ключей вне устройства не заводим; фраза восстановления отклонена.
- Восстановить единственного члена сообщества невозможно — некому быть спонсором.
