# ADR-0013: Схема ключей — эпохи с попарной раздачей

Статус: принято, 2026-09-17

## Контекст

Нужна смена группового ключа без сервера и без общего порядка событий. ADR-0012 снимает требования FS/PCS между членами. Состав меняется редко (после голосования), группы — десятки членов. Обзор: [research/group-keys.md](../research/group-keys.md).

## Решение

- Контекст (сообщество или чат) живёт эпохами; у эпохи случайный симметричный ключ.
- Новую эпоху создаёт событие **коммит**: список устройств-получателей + попарные объекты с ключом для каждого устройства.
- Изменение состава вступает в силу коммитом. «Предшествует удалению» в ADR-0004 = входит в причинное прошлое коммита.
- Конкурентные коммиты (форки) сводятся детерминированно: целевой состав = свёртка журнала, побеждает эпоха с целевым составом и наименьшим ID; если такой нет — любой член делает сливающий коммит. Обобщение правил SSB tribes2.
- Strong removal: коммит, конкурентный удалению своего автора, невалиден.
- Старые ключи хранятся (D6); сообщения из проигравшего форка остаются читаемыми.
- Только примитивы уровня libsodium; MLS и Double Ratchet не используем.

Детали — [design/03-keys.md](../design/03-keys.md).

## Последствия

- Стоимость коммита — O(число устройств) объектов.
- PCS только через коммит: удаление члена, отвязка устройства, плановая ротация (Q15).
- Окно: сообщения, написанные до того, как автор узнал о решении, читает и удалённый.
- Попарная раздача шифрует статическим ключом устройства — FS у ключевых объектов нет (ADR-0012).
- Смена эпохи сообщества — естественная точка смены пропуска к ретранслятору (Q13).
