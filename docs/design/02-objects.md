# Объект и конверт

Статус: черновик (2026-09-17). Следует из [ADR-0007, 0009, 0010, 0011](../adr/).

## Принцип

Единица хранения и синхронизации — **объект**: одно зашифрованное событие. Снаружи все объекты неотличимы. Что внутри, знает только тот, у кого есть ключ.

## Слои

```
Сессия синхронизации  — транспортное шифрование; член↔член: взаимная аутентификация ключами устройств; член↔ретранслятор: см. Q13; scope = одно сообщество
└─ Объект (открыто для любого члена-хранителя)
   ├─ ver        u8
   ├─ day        u16   грубое время (номер дня) — только для синхронизации и GC
   ├─ nonce      24 байта, случайный
   ├─ hint       8 байт = trunc(HMAC(k_hint_эпохи, nonce))
   └─ ct         AEAD(k_эпохи, nonce, inner), дополнен до корзины размера
      └─ inner (видно только владельцу ключа)
         ├─ chat_id, epoch
         ├─ author_device
         ├─ parents[]   ID объектов-родителей в DAG чата
         ├─ type, payload
         └─ sig         подпись author_device над всем inner
ID объекта = hash(объект целиком)
```

## Почему так

| Поле / решение | Зачем | Что было бы иначе |
|---|---|---|
| ID = хеш | дедупликация, проверка целостности без ключа, синхронизация по множествам ID | — |
| Нет `community_id` в объекте | сообщество задаётся сессией, A3 его не видит | — |
| Нет `chat_id` / `author` снаружи | D9: не-участник не связывает объекты в чаты и не видит автора | статичный тег чата раскрыл бы активность каждого чата |
| `hint` со случайным nonce | получатель узнаёт «свой» объект, перебрав известные ключи (O(ключей), в малых группах дёшево); для остальных — шум | статичный hint = тег чата |
| `parents` внутри | структура DAG не утекает | — |
| Подпись внутри | автор скрыт от не-участников (G2 проверяют только участники) | подпись снаружи раскрыла бы автора |
| Корзины размера (256 Б, 1 КБ, 4 КБ, 16 КБ) | размер не выдаёт тип события | — |
| `day` | Negentropy сортирует по (время, ID); грубое время почти ничего не раскрывает. Задел под GC для D6 | точное время = тайминги активности |
| Сообщество как «чат» | события членства — это объекты особого чата с ключом сообщества; формат один на всё | два формата |

Крупные данные после MVP: payload содержит корень Меркла, а куски — отдельные объекты того же формата.

## Синхронизация

- Каждый член хранит все объекты сообщества (D10). Набор = все ID, сверка через Negentropy по (`day`, ID).
- Ретранслятор (D11) участвует в той же сверке, но только хранит и отдаёт: `hint` не проверяет, расшифровать не может. Ретрансляторы сверяются и между собой (mesh).
- Ретранслятор может удалять объекты старше срока по `day` (Q14); члены — нет (NF1).
- Раз скачивается всё, по запросам нельзя понять, в каких чатах участвует член. D10 работает на D9.
- Получил объект → проверил хеш → сохранил → перебрал `hint` → если ключ нашёлся, расшифровал, проверил подпись и правила свёртки.

## Известные утечки и ограничения

- **Источник.** Пир или ретранслятор, получивший объект первым и напрямую, знает, от кого (с какого IP) он пришёл. Смягчение (после MVP): случайная задержка и пересылка через других.
- **Объём.** Не-участник видит общий объём объектов, которые не смог расшифровать.
- **Мусор.** Член может залить случайные объекты, неотличимые от секретного чата. Не-участники обнаружить это не могут, остаются только лимиты (G9, Q8).
- **Ключ `k_hint`** выводится из ключа эпохи (KDF), отдельно его не распространяем.

## Открыто

- Корзины размера и формат `inner` — в ADR о формате событий.
- Порядок проверки при конкурентной ротации эпох (объект пришёл раньше, чем ключ его эпохи) — отложенная очередь. Детали в синхронизации.
