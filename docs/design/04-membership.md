# Членство

Статус: черновик (2026-09-21). Решения: [ADR-0001](../adr/0001-kvorum-chlenstva.md), [0003](../adr/0003-multidevice.md), [0004](../adr/0004-strogoe-udalenie.md), [0005](../adr/0005-golos-po-polzovatelyu.md), [0008](../adr/0008-vstuplenie-po-qr.md), [0014](../adr/0014-zakrytie-zayavki-bez-chasov.md), [0015](../adr/0015-vosstanovlenie-dostupa.md). Эпохи, коммиты и валидность: [03-keys.md](03-keys.md).

Документ отвечает на один вопрос: **при каком множестве событий пользователь считается членом**. Момент вступления решения в силу — коммит новой эпохи — в 03-keys.

## Принцип

> Любой предикат членства вычисляется относительно **причинного прошлого** события, которое его задаёт, и никогда — относительно «текущего состояния».

| Следствие | Почему |
|---|---|
| Вердикт стабилен | причинное прошлое события зафиксировано хеш-ссылками; новые события в него не попадают |
| Отката состояния задним числом нет | пересчитывать нечего: тот же вердикт у всех, кто имеет событие и его прошлое |
| Свёртка не зависит от порядка доставки | G3.2 выполняется по построению |
| Часов в свёртке нет | `day` в конверте — только для синхронизации и GC (02-objects) |

Единственное исключение — **V3** (ADR-0004, строгое удаление): правило по смыслу смотрит вперёд, «не исключён ли автор коммитом, в причинное прошлое которого это событие не входит». Это единственный источник каскада V5 в системе.

## События

Все — объекты в контексте сообщества (02-objects), подписаны устройством автора.

| Событие | Автор | Содержание |
|---|---|---|
| `Propose` | устройство члена | `kind` = приём \| удаление \| перепривязка, `subject`; при приёме и перепривязке — ключ нового устройства и его подпись (ADR-0008, ADR-0015) |
| `Vote` | устройство члена | `proposal`, `value` = да \| нет |
| `DeviceBind` | устройство пользователя + новое устройство (взаимно) | `device_pub` |
| `DeviceUnbind` | устройство того же пользователя, **не** отвязываемое | `device` |

Коммит эпохи — отдельное событие, 03-keys. `Propose` на уже члена или удаление не-члена невалидно.

## Подсчёт голосов

| # | Правило |
|---|---|
| M1 | **Электорат** P = `members(causal_past(P))`; при удалении — минус `subject`, он не голосует |
| M2 | Голос V засчитывается, если: автор — устройство пользователя из электората; по `members(causal_past(V))` автор всё ещё член; P не закрыто в `causal_past(V)` |
| M3 | Голос — по пользователю (ADR-0005): из засчитанных голосов пользователя берётся причинно последний. Два конкурентных и различных → пользователь считается проголосовавшим **«нет»** |
| M4 | P **принято**, когда засчитанных «да» ≥ кворума |
| M5 | P **закрыто**, когда засчитанных «нет» столько, что кворум недостижим: `N − k + 1` от электората |
| M6 | Принятие и закрытие монотонны: голосов только прибавляется, вердикт не отменяется |

Электорат фиксируется в момент подачи, поэтому «сколько голосов нужно» известно сразу и показывается в интерфейсе.

M3 даёт отзыв голоса бесплатно: причинно более поздний голос вытесняет ранний. Тай-брейка по ID событий нет сознательно — он дал бы перебор, как подбор `epoch_id` в T3.

### Кворум

| Решение | Кворум `k` (MVP) | Откуда |
|---|---|---|
| приём | весь электорат (единогласие) | ADR-0008 |
| удаление | большинство электората без цели (> N/2) | здесь |
| перепривязка | весь электорат без цели (единогласие) | ADR-0015 |

Настраиваемость порога — после MVP; правила заморожены на момент создания сообщества.

В сообществе из двух удаление требует одного голоса: каждый может удалить другого, конкурентные взаимные удаления опустошают сообщество. Принято: в паре доверие симметрично.

## Закрытие заявки

Таймаута в свёртке нет (ADR-0014). «Заявка протухла» = принятие стало недостижимо, то есть M5. При единогласии это один голос «нет».

| Что защищаем | Механизм |
|---|---|
| **воскрешение**: год спустя последний член голосует «да», и входит тот, кому уже не место | M2 (голос после закрытия не считается) + M6 (закрытие монотонно) |
| висящий список в интерфейсе | локальные часы подсказывают «отклонить?»; решает человек, в журнал попадает обычный «нет» |

Локальное время влияет только на то, **когда человек действует**, и не входит в свёртку.

## Состояние

`members(S)` для причинно замкнутого множества событий S:

| # | Правило |
|---|---|
| S1 | создатель — член с генезиса; его электорат из одного, единогласие выполняется тривиально |
| S2 | принятый приём добавляет пользователя, принятое удаление убирает |
| S3 | при конкурентных принятых приёме и удалении одного пользователя побеждает **удаление** |
| S4 | повторный приём после удаления возможен только предложением, причинно следующим за удалением |

Порядок применения не важен (M6 + S3), поэтому свёртка детерминирована.

## Устройства

| # | Правило |
|---|---|
| U1 | первое устройство пользователя признаётся событием приёма — `Propose` несёт ключ кандидата (ADR-0008) |
| U2 | привязка — `DeviceBind`, подписанный уже признанным устройством пользователя и новым устройством |
| U3 | отвязка — `DeviceUnbind` от устройства того же пользователя, кроме отвязываемого |
| U4 | **каскад:** отвязка X отвязывает, рекурсивно, все устройства, привязанные событием от X, если их независимо не подтвердило другое устройство пользователя отдельным `DeviceBind` |
| U5 | устройства не голосуют — голос у пользователя (M3) |

U4 обязателен для PCS при A7b: держа ключ устройства X, противник привяжет им своё устройство Y, и отвязка одного X ничего не даст.

Привязка и отвязка меняют состав эпохи, но не состав сообщества → коммит нужен, голосование нет (03-keys, «когда делать коммит»).

## Восстановление доступа

Пользователь потерял единственное устройство: отвязать себя нечем (U3 требует другое его устройство), собственного голоса за себя нет (M1). Без отдельного правила остаётся повторный приём как **новый** пользователь — с разрывом биографии: прошлые сообщения остаются подписаны мёртвым ключом и приписаны тому, кого больше нет.

Перепривязка — решение о членстве по уже описанным правилам, а не отдельная машинерия (ADR-0015).

| # | Правило |
|---|---|
| R1 | `Propose` вида перепривязка подписывают устройство спонсора-члена **и** новое устройство цели (доказательство владения ключом); личность сверяется вне сети — тот же QR, что в ADR-0008 |
| R2 | цель должна быть членом по `members(causal_past(P))`; иначе предложение невалидно |
| R3 | электорат = `members(causal_past(P))` минус цель: своего устройства у цели нет, голосовать нечем |
| R4 | **вето цели:** голос «нет» с любого ещё живого устройства цели закрывает заявку (M5), хотя в кворуме «да» цель не считается |
| R5 | принятая перепривязка отвязывает **все** устройства цели, привязанные до P (с каскадом U4), и привязывает новое |

R4 закрывает угон личности у того, кто устройство не терял: телефон жив → человек накладывает вето. Телефон действительно потерян → вето некому наложить, и кворум проходит.

R5 покрывает и кражу: премиса перепривязки в том, что старым устройствам доверия нет.

Состав сообщества не меняется, состав эпохи меняется → нужен коммит, голосование за него не нужно (03-keys). Ключи прошлых эпох восстановленное устройство получает по настройке истории (ADR-0002) — «вернуть личность» и «вернуть архив» решаются независимо.

## Ограничения

| Ограничение | Статус |
|---|---|
| Окно: голоса тех, кто ещё не видел закрытия, засчитываются | по природе то же, что окно в G5.1 |
| Постоянно молчащий член блокирует любой приём | лечится его удалением, не протуханием заявки |
| При единогласии любой член в одиночку блокирует приём | принято для MVP (ADR-0008) |
| Скомпрометированное устройство голосует неотличимо от владельца | A7b, отдельный пункт повестки |
| Порог удаления и его настраиваемость | выбран здесь, не закреплён ADR |
| Перепривязка даёт кворуму то, чего не даёт удаление: писать **от имени** цели | смягчение только видимостью — событие перепривязки в журнале у всех, интерфейс обязан показывать смену устройства |
| Восстановление невозможно, если цель — единственный член | некому быть спонсором и электоратом |
| Уровень настройки истории до вступления | ADR-0002, открыто |
