# Ключи и эпохи

Статус: черновик (2026-09-17). Решения: [ADR-0012](../adr/0012-dva-urovnya-garantiy.md), [ADR-0013](../adr/0013-epohi-poparnaya-razdacha.md). Формат объектов: [02-objects.md](02-objects.md).

## Ключи

| Ключ | Чей | Тип | Назначение |
|---|---|---|---|
| `dev_sign` | устройство | Ed25519 | подпись событий (G2) |
| `dev_kx` | устройство | X25519 | приём попарных объектов |
| `k_epoch` | эпоха контекста | 32 случайных байта | корень ключей эпохи |
| `k_msg` = KDF(`k_epoch`, "msg") | эпоха | AEAD | шифрование объектов контекста |
| `k_hint` = KDF(`k_epoch`, "hint") | эпоха | MAC | hint групповых объектов |
| `k_relay` = KDF(`k_epoch`, "relay") | эпоха сообщества | — | кандидат в пропуск к ретранслятору (Q13) |

**Контекст** — сообщество или чат (в т.ч. секретный). У каждого свои эпохи. Члены эпохи — **устройства** членов контекста (D3).

Кандидаты примитивов (libsodium): Ed25519, X25519, XChaCha20-Poly1305 (nonce 24 байта = конверт), BLAKE2b для KDF, MAC и хешей. Выбор — ADR о крипто-библиотеке.

## Объекты

| Вид | Шифрование | Hint | Получатель узнаёт свой объект |
|---|---|---|---|
| Групповой | AEAD(`k_msg`) | MAC(`k_hint`, nonce) | перебор известных `k_hint` |
| Попарный | `ct` = `eph_pub` ‖ AEAD(KDF(X25519(eph, `dev_kx`))) | MAC(KDF(тот же DH), nonce) | один DH на объект |

Каждый входящий объект: 1 DH + по MAC на известный ключ эпохи. 100 тыс. объектов — секунды.

## Коммит

Групповой объект в **старой** эпохе (для генезиса контекста — попарные объекты без него):

| Поле | Значение |
|---|---|
| `prev` | ID эпох, которые коммит закрывает (1 — обычный, ≥ 2 — сливающий) |
| `reason` | ID решения (04-membership) / отвязки устройства / плановой ротации |
| `devices` | устройства новой эпохи |
| `epoch_id` | ID новой эпохи = hash(коммит) |

Плюс по одному **попарному** объекту на устройство из `devices`: `{epoch_id, k_epoch}`.
Новичку (приём, D2) — попарный **welcome**: ключ текущей эпохи и, если разрешено, ключи прошлых эпох.

Удалённый член видит коммит (состав), но не ключ.

## Валидность

| Правило | Суть |
|---|---|
| V1 | автор коммита — устройство члена эпох из `prev` и не удалён в причинном прошлом коммита |
| V2 | `devices` = целевой состав (T1) на момент причинного прошлого коммита |
| V3 (D4, strong removal) | коммит или сообщение устройства X невалидны, если не входят в причинное прошлое коммита, исключившего X |
| V4 | сообщение в эпохе E валидно, только если автор ∈ `devices(E)` |
| V5 | невалидное событие остаётся узлом DAG (родитель для других), но в состояние не попадает; потомки проверяются сами по себе |

## Текущая эпоха (сведение форков)

| Шаг | Правило |
|---|---|
| T1 | целевой состав = устройства членов по свёртке журнала контекста (для чата — ∩ членов сообщества) |
| T2 | кандидаты = эпохи-листья (не закрытые ни одним валидным коммитом) |
| T3 | текущая = кандидат с `devices` = целевому составу и наименьшим `epoch_id` |
| T4 | нет такого → любой член делает коммит с `prev` = все кандидаты; задержка со случайным разбросом |
| T5 | конкурентные сливающие коммиты сходятся по T3 |

T1 покрывает все случаи SSB (равные, вложенные, пересекающиеся составы).

## Когда делать коммит

| Триггер | Кто |
|---|---|
| решение о составе контекста принято | любой член, узнавший о нём (со случайной задержкой) |
| удаление из сообщества | то же во всех чатах, где был удалённый — их участники (G5.3) |
| привязка / отвязка устройства | любое устройство члена; при отвязке — не отвязываемое |
| T4 | любой член |
| плановая ротация | Q15 |

Член, узнавший о принятом решении, больше не пишет в старую эпоху: либо ждёт ключ, либо делает коммит сам.

## Ограничения

- Окно: сообщения тех, кто ещё не знает о решении, читает удалённый.
- Подбор `epoch_id` в T3 даёт члену преимущество — атака L2, принимается.
- Коммит — всплеск из O(устройств) попарных объектов: ретранслятор видит порядок размера сообщества (Q7).
- `eph_pub` X25519 статистически отличим от случайных байт: ретранслятор и члены могут отличить попарные объекты от групповых. Лечится кодированием Elligator2 (в libsodium нет, есть в Monocypher) — решить в ADR о крипто-библиотеке.
