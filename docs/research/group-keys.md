# Обзор: групповые ключи без сервера

Дата: 2026-09-17. Вывод → [ADR-0012](../adr/0012-dva-urovnya-garantiy.md), схема ключей → ADR-0013 (TBD).

## Подходы

| Подход | Суть | Порядок событий | FS / PCS | Для нас |
|---|---|---|---|---|
| MLS, RFC 9420 | дерево ключей (TreeKEM), Proposal/Commit | нужен сервер-упорядочиватель | сильные | в чистом виде не подходит |
| [DMLS](https://datatracker.ietf.org/doc/draft-kohbrok-mls-dmls/) (FREEK) | MLS с обработкой коммитов не по порядку | частичный | FS ослаблен | форки должны быть короткими |
| [Marmot](https://github.com/marmot-protocol/marmot) | MLS поверх ретрансляторов Nostr | детерминированное разрешение гонок коммитов (MIP-03) | как MLS | близко к нашим ретрансляторам; Rust (MDK) |
| DCGKA (Weidner, Kleppmann и др., 2021) | Double Ratchet для офлайн-групп | причинный | сильные | [p2panda-encryption](https://crates.io/crates/p2panda-encryption), «message encryption» |
| [BeeKEM](https://eprint.iacr.org/2026/1434.pdf) ([Keyhive](https://www.inkandswitch.com/keyhive/notebook/)) | TreeKEM со слиянием конкурентных изменений | причинный | FS ослаблен (κ > 1) | избыточен (тысячи членов) |
| [p2panda «data encryption»](https://p2panda.org/2025/02/24/group-encryption.html) | случайный ключ группы, попарная раздача O(n); новичку — все прошлые ключи; strong removal | причинный (DAG) | FS слабый; PCS при удалении или вручную | **ближе всего к нам** |
| [SSB tribes2](https://github.com/ssbc/ssb-tribes2) | эпохи; исключающий создаёт новую эпоху и раздаёт ключ | причинный; реплицируется всё | PCS при исключении | **правила слияния форков** |

## Правила слияния форков эпох (SSB, [exclusion spec](https://github.com/ssbc/ssb-group-exclusion-spec))

| Составы форков | Правило |
|---|---|
| равны | побеждает меньший ID ключа |
| один — подмножество другого | побеждает меньший |
| пересекаются частично | свидетели создают новую эпоху без исключённых из обоих |
| не пересекаются | разные контексты, слияния нет |

Известная слабость: выбор по ID ключа можно подыграть перебором.

## Термины

| Термин | Значение |
|---|---|
| FS (forward secrecy) | утечка ключа сегодня не раскрывает вчерашние сообщения |
| PCS (post-compromise security) | после утечки ключа и его смены противник снова не читает новые сообщения |
| CGKA | протокол, по которому группа договаривается об общем ключе и меняет его при изменении состава |
| Коммит (Commit) | событие, фиксирующее изменение состава и новый ключ |
| Форк эпохи | две разные «следующие эпохи», созданные одновременно в разорванной сети |
| Strong removal | удалённый не может никого добавить, даже одновременно со своим удалением |
| Попарная раздача | новый ключ группы шифруется отдельно для каждого члена его личным ключом |
| Double Ratchet | алгоритм Signal: ключ меняется на каждом сообщении |
